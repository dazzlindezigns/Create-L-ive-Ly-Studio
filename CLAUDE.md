# Create(L)ive(Ly) Studio — Claude Session Context

Order management + shop PWA for **Create(L)ive(Ly) Studio** (3D prints, custom gifts & keepsakes, brand merch, vendor essentials, digital papers). Her storefront today is Payhip at createlivelyinc.com; brand colors/fonts in `src/brand.js` come from that theme. Modeled on `dazzlindezigns/MakerQue-App` (DCIoS); see README.md for setup.

## Stack
- React 18 + Vite SPA, React Router v6
- Inline CSS style objects only (no Tailwind, no CSS modules). Shared pieces in `src/components/ui.jsx`.
- Theme: CSS variables `--primary --secondary --accent --plum --bg --card --card2 --dark --mid --muted --border --success --warning --danger`, set at runtime from `COLORS` in `src/brand.js`. `--accent` (#EFA2B3) is too light for text on white — use it only for gradients/decoration. Fonts: Playfair Display (headings), Montserrat (body).
- Shop products belong to a collection (`products.collection`, keys from `COLLECTIONS` in `src/brand.js`: labs, paper-studio, vendors, elevate). The shop filters via `?c=<key>` (or `?c=digital`).
- Supabase (anon key in browser; service role key only in `/api`)
- Vercel functions, ESM, `export default async function handler(req, res)`
- Stripe Checkout Sessions (form-encoded POST, `STRIPE_SECRET_KEY`; `api/_lib/stripe.js`), Resend, web-push, Anthropic SDK (`claude-opus-4-8` via `api/_lib/anthropic.js`, structured outputs via zod), Gemini image API (REST, `GEMINI_API_KEY`). No shipping-label integration — tracking is entered manually.

## Layout
- Public pages: `/` homepage (`Home.jsx`), `/custom` order form (only reached from CTAs; old `/?type=` and `/order` links still work), `/shop/products`, and `/p/:id` — one product on its own page for shared links (`ProductPage.jsx`; vercel.json rewrites `/p/:id` to `api/_handlers/product-page.js`, which serves the app shell with that product's title/photo/price as link-preview tags). Shop and product page share `useShop()`, `ProductDetail` and `CartModal` from `ShopProducts.jsx`. Public pages share `SiteHeader`/`SiteFooter` (`src/components/SiteChrome.jsx`).
- Responsive behavior uses the small class set in `src/index.css` (`container`, `grid-2`, `grid-4`, `hero-grid`, `order-grid`, `detail-cols`, `admin-sidebar`, `hide-desktop`…), because inline styles can't hold media queries. Admin pages render `<Nav>`, which adds `body.admin-layout` (desktop sidebar) and the phone bottom bar.
- The installable PWA is admin-only: `enableAdminApp()` in `src/lib/pwa.js` adds the manifest and iOS tags on `/dashboard` and `/login`. Don't put `<link rel="manifest">` back in `index.html`.

## Rules
- **Database changes go in a NEW file** `supabase/migrations/<YYYYMMDDHHMMSS>_<name>.sql`. Never edit a migration that already shipped. Supabase isn't connected to GitHub, so each new file must be pasted into the SQL Editor by hand: always tell the user the file's raw GitHub link and that it needs running. Keep migrations re-runnable (IF NOT EXISTS) and test them on a scratch Postgres first.
- **Brand values come from `src/brand.js`** — never hardcode the business name or hex colors. It's imported by both the app and `/api`, so keep it browser-API-free.
- **`po_number` and `internal_notes` are admin-only.** Never return them to customers. `publicOrder()` in `api/_lib/core.js` strips them; customer pages must use `/api/get-order`, never query `orders` directly.
- **Never trust client amounts.** Use `paymentOptions()` (`src/lib/money.js`) and `priceCart()` (`api/_lib/pricing.js`) server-side.
- **New API route:** add `api/_handlers/<name>.js` and register it in `api/[action].js`. Don't add top-level files in `/api` (Hobby plan has a 12-function limit). Throw `HttpError(status, msg)` for errors.
- Admin endpoints call `await requireAdmin(req)`; the browser sends the token via `api(path, { auth: true })`.
- Email HTML must escape user input with `esc()` / `escBr()` from `api/_lib/email.js`. Customer-facing emails pass `log: { orderId, kind }` to `sendEmail()` so they appear in the order's email history (`email_log` table, shown by `src/components/EmailPanel.jsx`). With `REPLY_DOMAIN` set, Reply-To becomes `order-<uuid>@REPLY_DOMAIN` so `api/resend-webhook.js` can match replies to orders; never forward into `REPLY_DOMAIN` (mail loop).
- AI calculator: `supplyLines[].qty` is the **total batch quantity** — don't multiply by `item.qty`.
- Column `stripe_payment_url` holds the latest Stripe Checkout link. Card payment is enabled per order by `'card'` in `payment_methods` (`'in_person'` is the other option). Each checkout is a `payments` row matched by `stripe_session_id`; the webhook claims the pending row once, so retries can't double-count.
- **Sticker Bar** is her sticker-sheet line (`STICKER_BAR` in `src/brand.js`, collection `sticker-bar`), not an event booking (`orders.event_details` is unused). A sheet is ONE physical product with `digital_price` + a private download file, so cart lines carry `format: 'digital'|'physical'`. **Stack & Save** applies to every product with `bulk_pricing_enabled` (tiers in `settings.stack_save_tiers`, falling back to the older `sticker_bar_tiers`; defaults `STACK_TIERS` in `src/brand.js`). Cart math is shared by the shop page and `priceCart()` through `src/lib/cart.js`, so change it there only.
- **Product options**: `products.option_groups` jsonb `[{ name, choices: [{ label, price }] }]` (price = change from the base price; physical format only). Cart lines send `selections` ({ Size: '4 inch' }); `resolveOptions()` in `src/lib/cart.js` validates them and adds the price changes for both the shop page and `priceCart()`. The old flat `products.options` list is read as one "Option" group and cleared on save. In the editor, one group can tick "Each choice has its own price": it shows full prices, and on save the cheapest becomes `products.price` and choices are stored as differences from it (the shop shows "from $X" and each choice's full price).
- `products.stock` (null = untracked) applies to physical units only. `priceCart()` refuses oversells, and `api/stripe-webhook.js` decrements via the `decrement_product_stock` RPC when a shop order is paid in full.
- **No AI vendor or "AI" wording in anything people see** (app, emails, errors, legal pages, screenshots): the features are the **Pricing assistant** (custom-request estimates / calculator), **Listing assistant** (`write-listing`), **Photo assistant** (`generate-listing-image`) and **Polish it** (email drafts). Vendor names stay in code, env vars and these docs only.
- **Get a price estimate** (pricing assistant) on a custom request opens `/dashboard/calculator?order=<id>`. `create-invoice` with `orderId` updates that order's quote in place (refused once payments exist). `estimate-from-description` takes `imageUrls` (public `order-files` only) and sends them to Claude as URL images.
- Admin pages read/write `settings`, `push_subscriptions` and `orders` straight through Supabase (RLS `is_admin()`), so the shop toggle, shop settings, notification sign-up and admin file uploads (`uploadFile(…, { auth: true })` → Storage RLS) keep working even if the API's service key is broken. `/api/health` checks the keys and VAPID setup.
- **Domain**: every link (emails, partner/product/review links, link previews) comes from `VITE_APP_URL` (server: `APP_URL` in `api/_lib/core.js`; browser: `src/lib/api.js`, falling back to the page's own address). Set it to `https://createlivelyinc.com` in Vercel (Production) and redeploy — Vite bakes it in at build. When it's set, `main.jsx` sends visits on `*.vercel.app` to the same page on that domain (`/api` webhooks on the Vercel address keep working).
- Admin menu: Orders, Inbox (`/dashboard/inbox`, replies + undelivered emails; badge counts `read_at is null`), Shop, Calculator; notifications/install are small links under Sign out (`AppLinks` in `Nav.jsx`).
- **Order flows** (`src/lib/status.js`): `orderFlow()` splits orders into shop (physical), digital (fulfillment 'digital' or every cart line a download) and custom. A paid digital order that isn't Complete gets a "✓ Mark complete" next step. Each has its own status list (`statusesFor`), step tracker (`stepsFor`) and one "next step" button (`nextStep`) on the order page; the status menu stays as a fallback. Shop/digital orders show "What they ordered" instead of the quote/proof sections; proofs show on custom orders once paid. Dashboard tabs: To do / Waiting / Done / All (shop checkouts unpaid after a day show as "Didn't pay"). Shop: paid → In production → ready/shipped → Complete. Picked up / delivered = Complete. Stage emails send automatically (next-step button, status menu, Mark shipped, refunds) — no checkboxes. Shop checkout has no notes or design uploads (items are made as shown; custom work goes to /custom). Shop orders ping her only once paid (no checkout-started push). PO numbers aren't used in this app (column kept, still stripped by `publicOrder()`).
- **Refunds** (`api/_handlers/refund-order.js`, `refundable()` in `src/lib/money.js`): full or partial. Card payments refund through Stripe first (`createRefund` in `api/_lib/stripe.js`), then other payments are only recorded. Each refund is a `payments` row (kind `refund`, `refund_of`); `orders.refunded_amount` keeps the total, and a full refund sets status `refunded` (locks downloads, optional restock via `restock_product`). Refunds made in the Stripe dashboard are not synced — refund from the app.
- **Partners (affiliates)** — branded **The LiveLy Circle** (`PARTNER_PROGRAM` in `src/brand.js`; hand emojis use the 🏾 skin tone): `affiliates` rows (code, rate % default 25, `own_discount` % default 25, `payout_method` + `payout_handle`, private `token`). Email is required; adding a partner sends the welcome email (`api/_lib/partners.js`, resend via `resend-partner-welcome`) with their page link. Partners can set their payment info on their page (`save-partner-payout`). "Shop for myself" on their page links to `/shop/products?partner=<token>`; `capturePartnerSelf()` remembers it and checkout sends `partnerToken`, which `create-shop-order` verifies and turns into their own-order discount (replaces any code; no commission). No login — the private token link is the access, like order links. `?ref=CODE` on any public URL is saved for `REF_DAYS` (30) by `captureRef()` (`src/lib/ref.js`, run in `main.jsx`; last link wins; `/api/track-ref` counts clicks) and sent with checkout. `create-shop-order` stores `affiliate_id` + `commission` (rate × items after discounts, before shipping; none for the partner's own email). `commissionFor()` in `src/lib/affiliates.js`: pending until the order is Complete, then ready; refunds shrink it; payouts set `commission_payout_id`. Admin page `/dashboard/partners` (linked from Shop); partner stats page `/partner/:token` (`get-partner`, no customer details). Shop orders only — custom requests aren't credited.
- **Reviews & feedback**: `/review/:orderId` (paid orders; `get-review` / `submit-review`) — star reviews per shop product (public, `reviews`, verified buyer, she can hide) plus private shopping feedback (`feedback`). Linked from the thank-you (completed) email, the download email and the customer order page. The order page has a Review & feedback card (Email review link / Copy text). A daily cron (`vercel.json` → `/api/review-reminders`, protected by `CRON_SECRET` when set) emails one `review_request` 5 days after `orders.completed_at` (set by a DB trigger) if there's no review or feedback; any review ask sets `review_reminder_sent_at`, so customers are asked once. Ratings come with `get-products` (`rating: { avg, count }`); `get-reviews` lists them on the product. Admin: Inbox → Reviews & feedback (counts toward the Inbox badge).
- **Refund policy** (`REFUND_POLICY` in `src/brand.js`): only ready-made physical shop items are refundable; digital downloads and custom orders are final sale. Shown on digital products, at checkout (required tick when the cart has downloads), on receipts and download emails, and in `QUOTE_TERMS`. The refund form still lets her refund anything but reminds her.
- Shop admin page shows only products (search + collection pills; "All" shows up to `ALL_PREVIEW` per non-empty collection with "See all"; the pick is kept in sessionStorage). Shop settings, Discount codes (list + "+ New code" form), Stack & Save and Option sets open as panels from pill buttons, next to LiveLy Circle, Reviews and Copy shop link.
- **Option sets** (`settings.option_sets`, helpers in `src/lib/optionSets.js`): reusable option groups (`{ id, title, name, choices }`). The product editor adds one with a tap (the group keeps `set: <id>`, which `optionGroups()` preserves) or saves any group as a set. Editing a set offers to update every product using it via `applySet()`, keeping each product's own choice prices.
- **Discount codes** have an optional `min_order` (cart after Stack & Save, before shipping); `cartTotals()` returns `codeShort` and `priceCart()` refuses below it. Codes are editable in Shop → Discount codes.
- Stage emails: changing an order's status to in production / ready for pickup / completed / declined sends a customer email automatically (`send-status-update`, which also sends payment reminders and receipt re-sends). Quote/invoice/receipt PDFs are the print view of `/quote/:id` (`OrderDocument.jsx`; `?print=1` opens Save-as-PDF).
- **Legal pages**: `/privacy` and `/terms` (`src/pages/Legal.jsx`), plain-language and built from `BRAND` (`contactEmail`, `legalState`, `legalUpdated`), `REFUND_POLICY`, `PARTNER_PROGRAM` and `REF_DAYS` — update `legalUpdated` whenever the wording changes. Linked from the footer, checkout, the custom request form, partner pages and the partner welcome email. The footer credits `BUILT_BY` (Dani Creates It → makeme.danicreatesit.com).
- **Create(L)ive(Ly) Finds** (`/finds`, `src/pages/Finds.jsx`; settings in `FINDS` in `src/brand.js`): her Amazon affiliate favorites styled as her own curated boutique — her photo, her "why I love it" note signed with her name, shelf pills, badges, one featured pick, "I use this to make → her product" links (`pairs_with`) and a homepage teaser. Rows live in the `finds` table (admin: Shop → Finds pill, `src/components/FindsManager.jsx`); `get-finds` serves them (only real Amazon links via `cleanAmazonUrl()` in `src/lib/finds.js`; "🔥 Popular" = top 3 by taps), `track-find` counts taps via sendBeacon while the link goes straight to Amazon (`rel="sponsored nofollow"`, no cloaking). Must keep Amazon's disclosure line (`FINDS.disclosure`) and must never present Amazon items as sold by her or show Amazon prices. She has no Amazon storefront or product API access, so finds are imported, not scraped: **Import my Amazon links** (`import-finds`) reads her Linktree (`FINDS.linktree`, via its `__NEXT_DATA__` JSON) or pasted links, keeps only Amazon links, resolves short links for the product words in Amazon's URL, and the listing assistant drafts a name, 2–3 note options (no invented facts), a shelf and an icon. Drafts (`draft = true`, `active = false`, `note_options`) wait under Review new finds until she publishes. Finds without her own photo show `TagArt` (a printed-label card: shelf, item name, "Curated by" line — typography only, no emojis) — never Amazon's images, which may only come from Amazon's API, unedited. Her full list is also shown via her Linktree ("Shop my full list" on `/finds`): `linktree-embed` checks Linktree's X-Frame-Options / CSP frame-ancestors and the page embeds it in an iframe when allowed, otherwise shows a plain "Open my full list on Linktree →" button (`/api/linktree-embed` reports `blockedBy` to show why). The photos stay on Linktree's page (its own Amazon connection); never copy them. Amazon's Creators API (product photos) needs an approved Associates account plus 10 qualifying sales in the past 30 days — she isn't eligible yet.
- **Affiliate partners** (`PARTNERS` in `src/brand.js`) render as homepage sections. Links use `rel="sponsored"` and must keep the visible commission `disclosure`.
- **AI listing photos** must start from her real product photo when one exists, and the prompt must keep the product unchanged (only restyle the scene) so listings don't misrepresent what ships.
- **Digital products** (`products.kind = 'digital'`): files go in the PRIVATE `digital-products` bucket; only `digital_file_path` is stored. Never select or return that path to customers (`get-products` omits it; `publicOrder()` strips `digitalFilePath` from `shop_cart`). Buyers get signed URLs only via `api/_handlers/get-downloads.js`, and only when paid in full. Shared logic lives in `api/_lib/downloads.js`.
